# Report a security issue privately

Email **security@zubda.co** with the affected endpoint or component, a minimal reproduction using synthetic data, potential impact and a safe contact method. Do not post vulnerabilities in public issues or discussions, and do not include real customer data, passwords or live API keys. Do not access another business's records or test disruptive attacks on production.

If a key is exposed, revoke it in Portal → Settings → Storefront API, create a replacement and remove it from logs and public history. Rotating alone leaves the old key valid until it is revoked or expires.

There is no guaranteed response time or bounty program promised by this policy.
