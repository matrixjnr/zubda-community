# Contribute

Questions belong in Q&A; proposals belong in Ideas. Explain the business problem, current workaround and expected behaviour before proposing an endpoint. Feature discussions are not commitments to delivery dates.

Pull requests may improve public documentation or add small server-side examples. Use synthetic data, environment variables for secrets, HTTPS, bounded timeouts and stable idempotency keys for order retries. Do not send payments or create production orders while testing examples. Explain validation in the pull request.

Do not contribute proprietary application source, customer exports, licensed third-party material, live credentials or unverified claims that a connector is production-ready. Keep documentation aligned with the published API contract.
